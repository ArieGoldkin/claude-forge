Conduct — routing work to an execution shape

/etk:auto-research answers which process a goal needs. /etk:conduct answers what shape that process runs in — including “none”. They are siblings, not nested. This brief explains both, the ladder underneath them, and the fleet mechanics that make a multi-lane run trustworthy.

The core discipline: the lowest rung that does the job. Escalation is a brake, not an accelerator. Most work items route to the leftmost rungs, and a fleet must be earned by classification — never assumed. Routing everything to a fleet is the fan-out-theater failure mode: five agents producing one agent’s insight five times.

1 Two routers, one pipeline

The two skills compose without either calling the other. A goal enters auto-research and leaves as a chosen skill; a work item enters conduct and leaves as a chosen topology. /etk:develop is neither a router nor a topology — it is the process that runs inside a lane.

Router A

/etk:auto-research

Input: a natural-language goal.
Question: which process?
Output: a skill — /develop, /fix-bug, /review-mr, /cover, /brainstorming, /verify…

Router B

/etk:conduct

Input: a work item or ticket.
Question: what execution shape?
Output: a topology — solo, one watched pane, sweep, broadcast, race, or a develop-fleet. Possibly no cmux at all.

They must not be merged. Conduct never re-routes a routed skill’s own sub-dispatch — the pipeline’s Phase-4 fan-out is /develop’s decision, not conduct’s. And conduct never invokes itself. A fleet that should run unwatched belongs to /auto-research --unattended (propose-only), not to conduct, which has no unattended mode by design.

2 The dispatch ladder — and the carve-out

Every agent in this repo excludes Agent/Task from its tools, so agents cannot spawn agents. The main loop is the orchestrator. That constraint is what makes a third tier look impossible — and the cmux carve-out is why it isn’t.

Cross-process carve-out. The no-nested-agents rule binds within one session. Each cmux pane runs an independent Claude Code session — its own main loop, with its own L0–L2 rights. So “orchestrator → lead → worker” is composition across sessions, never nested delegation. The fleet is how you reach a third tier without violating the ladder.

5 Fleet mechanics — spawn to verdict

    
Every step below exists because a simpler version of it was measured returning a wrong answer.

  O->>C: new-pane --type terminal --focus false, stderr captured
  C-->>O: OK surface 50, pane 8, workspace 3

errors go to stderr, so an ungated awk

  O->>C: rename-tab --surface REF, label at spawn
  Note over O,C: never a bare rename-tab.
it retitles the caller's own tab
  O->>C: send, cd worktree then claude with the one-line task
  O->>C: send-key enter
  C->>L: dispatch
  L->>F: writes findings, then a final STATUS line reading DONE
  C-->>O: notification created, a turn ended
  Note over O,F: the event says a turn ENDED,
not that the work succeeded
  O->>F: collect_lane, normalized last line
  F-->>O: rc 0 done, rc 1 not done, rc 2 escalate
  O->>O: payload gate, then slice-count assert
    

    
Three channels, three jobs — events say something happened,
      files say what the answer is, screens say whether anyone is home.


    

      

        
Why the verdict comes from a file

        
read-screen returns everything the surface shows — including the dispatch
        you just typed into it. Any sentinel you ask for is already on screen before the lane has
        done anything. Measured: a lane reported DONE the instant it was dispatched, and
        kept reporting DONE while sitting in an API-error retry loop having produced
        nothing. A file receives only what the lane wrote into it.

      

      

        
Why not a bare tail -n1

        
Agents end markdown files with a trailing blank line, bold the sentinel, or wrap it in a
        fence. Across 13 file shapes, tail -n1 produced 5 false negatives — safe,
        but it re-dispatches lanes that already succeeded at ~$0.57 each. collect_lane
        normalizes the last meaningful line, and still rejects the echoed instruction, a
        sentinel in a sentence, and a sentinel that is not last.

      

    


    

      
$TEAM must be absolute, and must not be a system temp dir. Lanes are
      dispatched with cd <worktree>, so a relative path resolves inside each lane’s
      own worktree — every lane writes a file the orchestrator never finds. And ctk’s
      security-blocker denies writes under the system temp roots, so a mktemp -d
      lane is blocked on its very first write. Use a path inside the repo, under a directory the repo
      already ignores.

    

  


  
  

    
6 The three gates — why one is not enough

    
collect_lane validates the sentinel. The reconcile reads a different
    field. So a lane can be honestly DONE and still poison the aggregate.

Measured: five distinct lane failures all produced 30 where the
      truth was 50. A lane that omits the field, one that writes a
      non-numeric value, and one that restates it twice all pass a sentinel-only gate.
      $((total + n)) treats an empty and a non-numeric n as
      0, in bash and zsh alike — no shell accidentally saves you. Same value, no warning,
      indistinguishable from a legitimate 30.

      
A partial fan-in must never publish an aggregate. When a slice is missing the run is
      DONE_WITH_CONCERNS at best, and the aggregate is withheld, not caveated.

    


    
The give-up bound — a retry is only a retry if you changed something

    
The census refuses a partial aggregate but never says how many times to try again.
    Re-sending an identical dispatch into identical conditions re-bills the full context for the
    same answer, so the bound is on undiagnosed rounds.

    

      

        
Gate resultBlind retriesInstead

        
          
rc=2 BLOCKED / NEEDS_CONTEXT0, everThe lane says it lacks something you did not give it. Answer the block and dispatch again carrying the answer, or escalate the text verbatim.

          
rc=1 no file / no verdict1, named causeDiagnose with --scrollback first: a bounded no-scrollback read once reported a working lane as dead.

          
payload gate1, quotableThe file is in hand, so the correction is exact — quote the lane its own output.

          
platform (classifier block, 529, retry loop)0 — waitNot in your prompt. One outage-bound lane measured $8.43 in a single round, ~8× its peers. An outage is a stop condition, not a retry condition.

        
      

    

    
A round cap is not a cost cap — one round is not a bounded cost. Check both the
      round counter and the spend before granting another; ≳3× the healthy-lane median is
      environmental, not promptable.

The ground-truth control is part of the system under test. The fleet disagreed with my
      reference and the fleet was right. A control gets less scrutiny precisely because it is
      the trusted side. When a result disagrees with your control, re-derive the control by a
      different mechanism before writing a word about the system being wrong.

      raised and then actually tested: no lane cites it, each records its own method, a third
      independent method reproduced the figures, and the source doc’s slice covered a different
      plugin set yet matched anyway. Computed, not copied.
