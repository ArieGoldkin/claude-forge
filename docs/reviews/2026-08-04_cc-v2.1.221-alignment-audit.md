# CC Alignment Audit — v2.1.194 → v2.1.221

> Audit date: 2026-08-04 · Running CLI **2.1.221** · Previously audited **v2.1.193** (2026-06-26)
> Gap: **28 versions**
> Status: **triage complete, two Tier-1 doc corrections measured.** Several Tier-2/3 items are
> deliberately left as *hypotheses* rather than findings — see "Method" for why that matters here.

## Method — and the failure this audit is written to avoid

The previous audit produced a claim that was wrong for five weeks. Root `CLAUDE.md` records the
cause exactly:

> *"The false claim originated in a CHANGELOG gap-analysis that verified the conditions were
> **present** and never that they **gate**."*

It read a CHANGELOG entry (the v2.1.176 hook `if`-condition fix), observed that our `hooks.json`
*had* `if` conditions, and concluded our hooks depended on that fix. Measured later (#98): none of
the six conditions ever gated anything.

So the rule for this pass: **a CHANGELOG entry is a hypothesis, never a finding.** Nothing below is
stated as affecting this repo unless it was measured against the repo or the binary. Where a claim
is *not* measured, it says so in the entry rather than in a footnote.

## Tier 1 — our own docs are now wrong (both MEASURED)

### T1.1 — The subagent nesting limit in root `CLAUDE.md` is two revisions stale

`CLAUDE.md:450` states:

> *"Since CC v2.1.172 subagents can spawn their own subagents; v2.1.180 raised the limit to 5 levels
> deep…"*

Superseded **twice** since:

| Version | Change |
|---|---|
| 2.1.217 | *"Changed subagents to no longer spawn nested subagents by default; set `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` to allow deeper nesting"* |
| 2.1.219 | *"Subagents can now spawn nested subagents up to depth 3 by default (was 1); set `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` to disable nesting"* |

So the live default is **depth 3**, not 5, and it passed through **1** in between.

⚠ **MEASURED — the sentence's *parenthetical* is still true, and only the number is wrong.** The
same line says *"every agent in this repo currently excludes `Agent`/`Task` from its `tools:` list,
so nesting is disabled by configuration here."* Re-measured: **0 agent files declare `Agent` or
`Task` in `tools:`**. The repo is unaffected in behaviour; the *documented platform limit* is what
rotted. Fix the number, keep the parenthetical.

### T1.2 — 11 skills changed execution mode and nothing in the repo says so

2.1.218: *"Changed skills with `context: fork` to run in the background by default; opt out per
skill with `background: false`."*

**MEASURED:** **11** `SKILL.md` files declare `context: fork`. **None** declare `background:`, so
**all 11 take the new background-by-default.**

**CONFIRMED BY DIRECT OBSERVATION this session, not by inference:** `/etk:review-mr` was invoked
three times and each time returned *"Running in the background as `@etk-review-mr`"*, delivering its
report via a task-notification rather than inline. That is 2.1.218 in effect.

Why it matters beyond bookkeeping: `review-mr`'s SKILL.md carries an explicit **return contract**
("the fork's final message is the only thing the caller sees") whose stated failure mode is a skill
that *"silently returns nothing to the caller, which is indistinguishable from the skill being
dead"* — a regression it records as having shipped twice. The contract still holds, but the
**delivery path is now a background task notification**, which is a different way for a report to go
missing. The ledger's older note that *"a PreToolUse deny is terminal for a fork"* was written
before this change and should be re-read against background execution.

⚠ **NOT MEASURED:** whether a denial or crash inside a *background* fork surfaces differently from
one inside an inline fork. The three runs this session all succeeded, so the failure path is
unobserved. Do not assume the old fork-termination behaviour carries over unchanged.

## Tier 3 — governance/settings changes that touch documented advice

⚠ **Every item here is UNMEASURED and is exactly the shape that produced the last false floor note.
Do not copy any of it into `CLAUDE.md` without probing first.**

- **2.1.207 — `autoMode` is no longer read from repo-resident `.claude/settings.local.json`; use
  `~/.claude/settings.json`.** Root `CLAUDE.md` currently advises configuring auto-mode in
  *"`~/.claude/settings.local.json` (gitignored, per-developer)"*. The CHANGELOG drops the
  **repo-resident** path; whether a **user-level `.local.json`** is still honoured is **not stated
  and not measured**. The two paths differ, and the naive reading — "our advice is wrong" — is
  precisely the inference that went wrong last time. **Probe before editing.**
- **2.1.207 — `pluginConfigs` no longer read from project-level `.claude/settings.json`.** We ship
  no plugin options today (measured: no `user_config` anywhere), so this is likely inert here.
- **2.1.211 — a PreToolUse hook's `ask` decision now floors auto mode at a prompt.** ADR-0002 chose
  to *withhold* approval rather than emit `ask`, reasoning that an `ask` gate *"would override the
  user's own `permissions.allow`."* This entry changes how `ask` composes with auto mode. It does
  **not** automatically invalidate the ADR — the ADR's concern was the user's allowlist, not auto
  mode — but the trade-off it recorded was priced against older behaviour and deserves a re-read.
- **2.1.212 — Task tool's `mode` parameter deprecated; subagents inherit the parent's permission
  mode.** Matches what our tool description already says; no known conflict.

## Recommended sequencing

1. **T1.1 — correct the nesting number** in root `CLAUDE.md` (one line; keep the parenthetical,
   which re-measured true). Lowest risk, purely factual.
2. **T1.2 — document the `context: fork` background default** where the fork contract lives, and
   re-read the "denial is terminal for a fork" note against background execution. ⚠ The failure path
   is unobserved — say so rather than assuming it carries over.
3. **Tier 3 auto-mode settings path — probe, then edit.** A three-cell settings experiment answers
   it. Note that the equivalent probe in #98 was **blocked by the auto-mode classifier** and was
   correctly not worked around; expect the same and plan for it.
4. Tier 2 items are optional adoptions with no defect behind them; ADR-0002's triage rule applies —
   a listed capability is not a work item until something needs it.

## What this audit did NOT do

- **No behavioural probes were run.** This is a triage pass: it establishes *which* of 28 versions
  could touch this repo, and measures the repo-side facts (what we ship, what we declare). The
  platform-side behaviour of every Tier-2/3 item is unverified.
- **The CHANGELOG was read once, from `raw.githubusercontent.com`.** It was not cross-checked
  against the binary except where noted.
- **T1.2's evidence is an observation of three successful runs**, not an experiment. It establishes
  that fork skills *do* run in the background now; it establishes nothing about their failure modes.
